Lesson 5 — "groundedness" is four different measurements

An open-book exam has four places it can go wrong. So does a document-answering agent.

The pipeline, with a checkpoint at each stage

1 · the question"What's the hotel cap for Berlin?"
↓  the search runs
2 · the documents it foundThree chunks of policy text
context recallDid it find the pages that actually contain the answer?
context precisionOf the pages it did find, how many were relevant?
↓  the agent reads them and writes
3 · the answer"The cap is EUR 200 per night."
faithfulnessDoes the answer stick to what those pages said?
answer relevanceDoes it answer the question that was asked?

Four checkpoints, each comparing a different pair of things. That's why they can't be one number: recall compares found documents against documents that existed, while faithfulness compares the answer against the found documents. Different inputs, different failure, different repair.

The pair you keep asking about

First, a correction to what I told you in the preview I said s04's search was "fine-ish" and the agent was the problem. That was wrong. The numbers say s04's recall is 0.00 — its search failed just as completely as s05's. I was going from memory instead of measuring. The real story is better than the one I previewed.

Identical retrieval failure. Opposite agent behaviour.

Both searches returned nothing containing the answer. Recall 0.00 for each.

s04
recall 0.00 — never found the hotel-cap page
faithfulness fail — stated "EUR 200 per night" and cited a section it had never seen
s05
recall 0.00 — never found the France rate page
faithfulness pass — "I couldn't find it, I'd rather not guess"
Why this matters: both need the search fixed — the answer was in the corpus both times. But only s04 also needs the agent fixed, because an agent that invents a number when it finds nothing is dangerous in a way that one which says "I don't know" is not.

One number cannot tell you that. You need recall and faithfulness side by side to see that the retrieval bug is shared and the agent bug isn't.

Two more things the numbers show

s02 — recall explains the faithfulness failure

Recall 0.50: it found the rates table, it missed travel-02-perdiem#03 — the chunk containing the travel-days rule.

Which is exactly the claim you flagged as unsupported: "departure and return days are reimbursed at 50%". The recall number tells you why faithfulness failed, and names the missing chunk. That is the difference between a score and a diagnosis.

Precision is 0.33 on almost every conversation

The search is set to return 3 chunks. Usually only 1 is relevant.

So roughly two thirds of everything handed to the agent is noise — every single time. No individual conversation fails because of it, which is exactly why nobody notices. It only shows up when you measure the same thing across all eight. The agent is paying for, and reading, twice as much irrelevant text as relevant.

What you can now do that you couldn't before Open any eval platform's RAG metric list — Braintrust, Galileo, Foundry, Ragas, anything — and you'll see four or five names that all sound like "is the answer right". You now know each one compares a specific pair of things, and which repair each failure points to.

A single "groundedness: 0.6" tells you something is wrong. Recall 0.00 with faithfulness fail tells you to fix the search and stop the agent guessing.
