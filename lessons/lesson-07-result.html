The four ways, run on s07

Average the turns misleading

0.80

4 good turns, 1 bad turn = 80%. On a dashboard that looks like a strong session. But the user came to file a claim, and the claim was never filed. They got 0% of what they came for. The average hides the only turn that mattered.

Any failed turn fails it right here, wrong elsewhere

Fails s07 correctly. But it's too harsh in general. Imagine the agent gets a number wrong in turn 2, the user corrects it, and the agent fixes it in turn 3 and finishes the job. The user got everything they wanted. This method still fails the whole conversation for a mistake that was recovered.

The last turn decides right by luck

Fails s07 correctly, but only because the important request happened to come last. If the user had asked "submit it" in turn 3 and then said "thanks" in turn 5, the last turn would pass and the missed submission would be invisible.

Did the user's main goal happen your choice

The user came to file a claim. By the end of the conversation, was it filed? No. → fail.

It doesn't care how many turns went well, or where the important turn sat, or whether there were recovered mistakes along the way. It asks the one question the user cares about.

You already had this

In Lesson 3 you wrote the task-completion rule: "extract the task what user said and each turn check whether the task was completed or not, if not completed until the end then fail it." That is goal-based session scoring. It scored 8/8. Today's choice is the same idea, now with a name.

The takeaway for your decisions file Score turns to find where something went wrong. Score the goal to decide whether the session succeeded. Never average turns into a session score — a session where 4 of 5 turns were good and the user still left empty-handed is a failed session, not an 80% session.
