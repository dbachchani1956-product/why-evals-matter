2. Label — this is where you went wrong

your answer: wrong, and worth getting right

You described a category tag — "the label the creator puts, like booking". That is a real thing, but it is not what label means in evaluation. The word is overloaded, which is exactly why this trips people.

WHAT YOU DESCRIBED

Intent tag / metadata

A category attached beside the trace so you can filter and group. Usually set automatically, by the system.

intent = "cancellation"
channel = "web"

Answers: which kind of conversation is this?
Use: slicing dashboards — "how do we do on cancellations?"
Says nothing about whether this one was any good.

WHAT EVAL MEANS

Ground truth / label

A verdict you write above the trace, saying what should have happened. Always produced by a human.

verdict = FAIL
reason = "never told the user
the €412 refund amount"

Answers: was this conversation correct?
Use: the answer key every scorer gets checked against.
This is the thing without which no metric can be shown to work.

Why the confusion is reasonable In classification machine learning, the label is the category — "this email is spam". In evaluation, the label is the correctness verdict — "this conversation failed, here's why". Same word, different job. Platform docs rarely say which one they mean.
You, afterwards · ground truth

3. Trajectory

your answer: right shape, missing the reason

You said it's the path — source → reason → lookup → reason → reply. Correct. But you framed it as "important to evaluate and answer". Here's the sharper reason it matters.

The answer and the path can be right or wrong independently. Four combinations exist, and three of them are failures that a scorer looking only at the final reply will completely miss:

Path was rightPath was wrong
Answer right Genuinely fine Looks fine, isn't. Cancelled the booking without ever confirming identity. Right outcome, dangerous process. Happened to work this time.
Answer wrong Blameless but still failed. Did everything correctly, the cancellation API returned an error, user didn't get cancelled. Obviously broken
This is why agent eval exists as a separate discipline For a chatbot, the reply is the product, so scoring the reply is enough. For an agent, the reply is one artifact of a path — and the path can confirm no identity, call a destructive tool twice, or skip a required check, while the reply reads perfectly. You will meet exactly this in our own traces.

4. Rubric

your answer: strong — better than most first attempts

You said: a set of criteria, like did the agent confirm identity, did the cancellation API error, did the agent inform the user of the refund amount. The criteria instinct is right, and your criteria are specific and checkable, which is the hard part. Two gaps.

Gap 1 — criteria are only half of a rubric. The other half is levels: what each possible score actually means, so two different reviewers reach the same verdict. Your criteria with levels added:

CriterionPassFail
Confirmed the user's identity before cancelling agent Asked for and received a booking reference or equivalent before the cancel call Called cancel first, or never asked
Told the user the refund amount agent A specific figure appears in the reply No figure, or vague — "you'll be refunded"
Stated the cancellation terms agent Named the deadline or fee that applied Silent on terms
The cancellation API returned an error not the agent ⚠️ This one doesn't belong here — see below
Gap 2 — one of your criteria scores the wrong actor "Did the cancellation API error" is a tool fault, not an agent decision. Put it in a rubric that scores the agent and a good agent gets marked down for a backend outage — so the score stops telling you what to fix.

It is still worth measuring. It just belongs in a different scorer, one that asks "did the user get what they wanted?" rather than "did the agent behave well?". Those two questions genuinely differ, and keeping them apart is what makes a failing score actionable.

The rule: one rubric, one actor. Decide whether you are grading the agent or the whole system, and don't mix them in the same score.

Notice what your rubric form actually is: a checklist of binary pass/fail criteria, rather than a 1–5 quality scale. That is a deliberate style — a checklist rubric — and for agent behaviour it is usually the better choice, because "did it confirm identity" has a real answer while "how good was this conversation, 1 to 5" does not. You picked the stronger form without being told to.
